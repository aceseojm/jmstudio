MCP란? AI가 다른 도구와 연결되는 방식

“AI한테 우리 캘린더를 보고 빈 시간을 찾아 달라고 할 수 있나요?” 요즘은 됩니다. 그 연결을 가능하게 하는 공통 규격이 MCP입니다. 개발 용어처럼 들리지만, 원리는 생각보다 단순합니다.

JM Studio2026년 11월 15일읽는 시간 9분개념 정리
세 줄 요약
  • MCP는 AI 앱을 캘린더, 문서, 데이터베이스 같은 외부 서비스에 연결하는 공통 규격입니다. 공식 문서는 “AI를 위한 USB-C”에 비유합니다.
  • 서비스마다 연결을 따로 만들던 일을 한 번 만들면 여러 AI 앱에서 쓰는 방식으로 바꿨습니다.
  • 연결이 쉬워진 만큼 어떤 서버를 붙이고 어디까지 허락할지는 더 신중하게 정해야 합니다.

MCP란

MCP(Model Context Protocol)는 AI 앱을 외부 시스템에 연결하기 위한 공개 표준입니다. 공식 문서의 설명을 옮기면, MCP를 쓰면 Claude나 ChatGPT 같은 AI 앱이 파일·데이터베이스 같은 데이터, 검색엔진·계산기 같은 도구, 미리 만든 작업 지시 같은 워크플로에 연결해 정보를 가져오고 일을 처리할 수 있습니다.

USB-C에 비유하면: 예전에는 기기마다 충전 단자가 달라 케이블을 따로 챙겨야 했습니다. USB-C는 하나의 규격으로 여러 기기를 연결합니다. MCP는 AI 앱과 외부 서비스 사이의 USB-C 역할을 합니다.

MCP는 2024년 11월 Anthropic이 오픈소스로 공개했습니다. 2025년 12월에는 리눅스 재단 산하의 Agentic AI Foundation에 기증되어, 한 회사가 아닌 중립적인 재단이 관리하는 표준이 되었습니다. 당시 발표에 따르면 ChatGPT, Gemini, Microsoft Copilot, Cursor, Visual Studio Code 같은 제품이 MCP를 지원합니다.

왜 필요했을까

AI는 똑똑해도 우리 캘린더나 예약 장부를 직접 볼 수는 없습니다. 그래서 AI 앱과 서비스를 잇는 연결을 따로 만들어야 했는데, 이 연결은 AI 앱과 서비스의 조합마다 새로 만들어야 했습니다. AI 앱이 3개, 서비스가 3개면 연결이 9개 필요한 셈입니다.

MCP는 이 사이에 공통 규격을 하나 둡니다. 서비스는 MCP 규격으로 한 번만 연결 창구를 만들고, AI 앱은 MCP 규격만 알면 그 창구를 모두 쓸 수 있습니다.

세 가지 역할: 호스트, 클라이언트, 서버

공식 문서의 구조 설명에는 세 가지 역할이 나옵니다.

H

MCP 호스트Host

사람이 쓰는 AI 앱입니다. Claude 데스크톱 앱, Visual Studio Code 같은 프로그램이 여기에 해당합니다.

C

MCP 클라이언트Client

호스트 안에서 서버 하나와의 연결을 맡는 부품입니다. 서버를 세 개 연결하면 클라이언트도 세 개 생깁니다. 사용자가 직접 볼 일은 거의 없습니다.

S

MCP 서버Server

외부 서비스의 기능과 정보를 MCP 규격으로 내어 주는 프로그램입니다. “캘린더 MCP 서버”, “파일 시스템 MCP 서버”처럼 서비스마다 있습니다.

서버는 내 컴퓨터에서 돌 수도 있고(로컬 서버), 서비스 회사의 인터넷 서버에서 돌 수도 있습니다(원격 서버). 예를 들어 내 컴퓨터의 파일을 읽는 서버는 로컬에서, 클라우드 서비스가 직접 제공하는 서버는 원격으로 연결합니다.

서버가 주는 세 가지: Tools, Resources, Prompts

공식 문서에 따르면 MCP 서버는 세 가지를 제공할 수 있습니다. 누가 쓰기로 결정하는지가 서로 다릅니다.

무엇인가예시누가 고르나
Tools
(도구)		AI가 직접 실행하는 기능. 정보를 바꾸거나 외부에 요청할 수 있음일정 만들기, 메시지 보내기, 항공편 검색AI 모델
Resources
(자료)		읽기만 하는 참고 정보문서 내용, 데이터베이스 구조, 캘린더 조회AI 앱
Prompts
(지시 템플릿)		도구와 자료를 어떻게 쓸지 미리 만든 작업 지시“회의 요약하기”, “메일 초안 쓰기”사용자

이 중 가장 많이 쓰이는 것은 Tools입니다. 공식 문서는 도구를 실행하기 전에 사용자의 동의를 받도록 할 수 있다고 설명합니다. AI가 일정을 지우거나 메일을 보내기 전에 사람이 확인하는 장치입니다. Tool이라는 말이 낯설다면 Agent와 Node 그리고 Tool의 차이가 궁금해요를 먼저 읽어 보셔도 좋습니다.

실제로는 이렇게 움직입니다

작은 공방이 AI 앱에 캘린더 MCP 서버를 연결해 두었다고 해 봅시다. 대표가 이렇게 묻습니다.

MCP로 캘린더를 연결한 AI 앱
다음 주에 2시간짜리 원데이 클래스를 넣을 수 있는 시간이 언제야?
다음 주 캘린더를 확인했습니다. 화요일 오후 2~4시와 목요일 오전 10~12시가 비어 있습니다. 화요일로 일정을 잡을까요?사용한 도구: 캘린더 › 일정 조회

대표가 “응”이라고 답하면 AI가 “일정 만들기” 도구를 실행합니다. 실행 전에 확인을 받도록 설정할 수 있습니다.

그 뒤에서는 이런 일이 일어납니다.

  1. AI 앱(호스트)이 캘린더 서버에 “어떤 도구가 있니?”라고 묻고, “일정 조회”, “일정 만들기” 같은 목록을 받습니다.
  2. AI 모델이 질문을 읽고 “일정 조회” 도구가 필요하다고 판단합니다.
  3. AI 앱이 서버에 조회를 요청하고, 결과를 받아 AI 모델에게 건넵니다.
  4. AI 모델이 빈 시간을 정리해 답합니다.

캘린더 대신 노션, 구글 드라이브, 사내 데이터베이스여도 순서는 같습니다. 이것이 공통 규격의 힘입니다.

API, 자동화 툴과는 무엇이 다를까

“그럼 API랑 같은 거 아닌가요?”, “n8n 같은 자동화 툴이 필요 없어지나요?”라는 질문을 많이 받습니다. 셋은 경쟁 관계가 아니라 층이 다릅니다.

APIMCP자동화 툴(n8n·Make 등)
한마디로서비스가 여는 문AI가 그 문을 쓰는 공통 규격정해진 흐름을 자동 실행하는 도구
누가 쓰나개발자가 만든 프로그램AI 앱과 AI 모델미리 짜 둔 워크플로
언제 움직이나호출할 때AI가 대화 중 필요하다고 판단할 때정해진 시간이나 이벤트가 생길 때
잘하는 일정확한 데이터 주고받기그때그때 다른 요청에 맞춰 도구 고르기매번 같은 일을 빠짐없이 반복하기

MCP 서버는 대개 서비스의 API를 감싸서 만듭니다. 그러니 MCP가 API를 없애는 것이 아니라 API 위에서 AI가 알아듣기 쉽게 정리해 주는 층입니다. 자동화 툴과도 함께 쓸 수 있어서, n8n은 워크플로 안에서 MCP 서버에 연결하는 기능을 제공합니다. 둘의 역할 차이는 AI가 똑똑해졌는데 자동화 툴이 아직 필요할까?에서 자세히 다뤘습니다.

연결할 때 주의할 점

MCP는 AI에게 손발을 달아 주는 일입니다. 편해지는 만큼 조심할 것도 생깁니다.

믿을 수 있는 서버만 연결합니다

MCP 서버는 누구나 만들어 공개할 수 있습니다. 서비스 회사가 직접 만든 공식 서버인지, 누가 관리하는지 확인하고 연결하세요. 출처가 불분명한 서버는 내 파일이나 계정에 접근할 수 있는 프로그램을 설치하는 것과 같습니다.

권한은 필요한 만큼만 줍니다

일정을 조회만 하면 되는 일에 삭제 권한까지 줄 필요는 없습니다. 읽기 전용으로 시작하고, 쓰기 권한은 꼭 필요할 때 범위를 좁혀 추가합니다.

되돌리기 어려운 일은 확인을 거칩니다

메일 발송, 결제, 삭제처럼 되돌리기 어려운 도구는 실행 전에 사람이 승인하도록 설정합니다. AI에게 어디까지 맡길지는 AI 에이전트에게 어디까지 맡겨도 될까?에 기준을 정리했습니다.

외부 글 속의 지시를 경계합니다

AI가 MCP로 읽어 온 메일이나 웹페이지 안에 “이 내용을 무시하고 파일을 보내라” 같은 문장이 숨어 있을 수 있습니다. 이런 공격을 프롬프트 인젝션이라고 부릅니다. 외부 내용을 읽는 도구와 중요한 작업을 하는 도구를 함께 연결할 때는 특히 승인 단계를 두는 것이 안전합니다.

우리에게 필요할까

MCP는 개발자만의 이야기가 아닙니다. 아래 중 해당하는 것이 있다면 MCP가 쓸모 있습니다.

  • AI 채팅을 쓰면서 캘린더·문서·메일 내용을 복사해 붙여 넣는 일이 잦다
  • 쓰고 있는 업무 도구(노션, 구글 드라이브 등)가 MCP 서버를 제공한다
  • 우리 예약 시스템이나 고객 데이터를 AI가 조회해 답하게 하고 싶다
  • 같은 연결을 여러 AI 앱이나 직원들이 함께 쓰고 싶다
  • AI가 대화 중에 상황에 맞는 도구를 골라 쓰는 상담·업무 비서를 만들고 싶다

반대로 “매일 오전 9시에 주문 목록을 정리해 메일로 보낸다”처럼 흐름이 정해진 일이라면 MCP보다 자동화 워크플로가 더 맞습니다. 쓰는 서비스에 공개된 MCP 서버가 있다면 연결 설정만으로 시작할 수 있고, 우리만의 시스템이라면 MCP 서버를 새로 만들어야 합니다.

자주 묻는 질문

MCP란 무엇인가요?

MCP(Model Context Protocol)는 Claude나 ChatGPT 같은 AI 앱을 파일, 데이터베이스, 캘린더, 업무 도구 같은 외부 시스템에 연결하는 공개 표준입니다. 공식 문서는 AI 앱을 위한 USB-C 포트에 비유합니다. 2024년 11월 Anthropic이 공개했고, 2025년 12월 리눅스 재단 산하 Agentic AI Foundation에 기증되었습니다.

MCP와 API는 무엇이 다른가요?

API는 각 서비스가 저마다의 방식으로 여는 문이고, MCP는 AI 앱이 그런 문을 같은 규격으로 쓰게 해 주는 약속입니다. MCP 서버는 보통 서비스의 API를 감싸서, 어떤 기능이 있는지와 어떻게 부르는지를 AI가 알아들을 수 있는 형태로 알려 줍니다. MCP가 API를 대체하는 것이 아니라 API 위에서 동작합니다.

MCP를 쓰려면 개발을 해야 하나요?

이미 MCP 서버가 공개된 서비스라면 지원하는 AI 앱에서 연결 설정만으로 쓸 수 있는 경우가 많습니다. 우리 회사의 예약 시스템이나 내부 데이터베이스처럼 공개된 서버가 없는 시스템을 연결하려면 MCP 서버를 새로 만들어야 합니다.

MCP가 있으면 n8n이나 Make 같은 자동화 툴은 필요 없나요?

역할이 다릅니다. MCP는 AI가 대화 중에 필요한 도구를 골라 쓰게 하는 연결 방식이고, 자동화 툴은 정해진 시간이나 이벤트에 정해진 흐름을 매번 같은 방식으로 실행합니다. n8n처럼 MCP 연결을 지원하는 자동화 툴도 있어 함께 쓰는 경우가 많습니다.

우리 시스템을 AI와 연결하고 싶다면

예약 장부, 고객 자료, 사내 문서처럼 AI가 함께 봐야 할 시스템을 알려 주시면, MCP로 연결할지 자동화 워크플로로 만들지부터 함께 정해 드립니다.
