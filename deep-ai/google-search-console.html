구글 서치 콘솔, 처음 시작하는 법

홈페이지를 만들고 나면 “구글에 등록은 어떻게 하나요?”라는 질문이 꼭 나옵니다. 그 답이 구글 서치 콘솔(Google Search Console)입니다. 속성 추가와 소유권 확인, 사이트맵 제출까지 처음 한 번 해 두어야 할 일과, 그다음부터 들여다볼 보고서를 구글 공식 도움말을 기준으로 정리했습니다.

JM Studio2026년 11월 3일읽는 시간 9분도입 가이드
세 줄 요약
  • 서치 콘솔은 내 사이트가 구글 검색에서 어떻게 보이는지 확인하는 무료 도구입니다.
  • 처음에는 속성 추가 → 소유권 확인 → 사이트맵 제출 세 단계만 하면 됩니다.
  • 등록이 검색 노출을 보장하지는 않습니다. 대신 색인 상태와 검색 실적, 문제를 직접 확인할 수 있게 됩니다.

기준일: 이 글은 2026년 11월 기준 구글 Search Console 고객센터 문서를 바탕으로 썼습니다. 메뉴 이름과 세부 기준은 바뀔 수 있으니 작업할 때 공식 문서를 함께 확인하세요.

서치 콘솔은 무엇을 하는 도구인가

구글 서치 콘솔은 사이트 운영자가 구글 검색에서 내 사이트의 상태를 확인하고 관리하는 무료 도구입니다. 구글 계정만 있으면 쓸 수 있습니다. 주로 이런 일을 합니다.

  • 알리기: 사이트맵을 제출해 구글에 페이지 목록을 알립니다.
  • 확인하기: 어떤 페이지가 구글 색인에 들어갔는지, 안 들어갔다면 이유가 무엇인지 봅니다.
  • 살펴보기: 어떤 검색어로 몇 번 노출되고 몇 번 클릭됐는지 봅니다.
  • 알림 받기: 사이트에 문제가 생기면 메일로 알림을 받습니다.

네이버에서 같은 역할을 하는 도구가 서치어드바이저입니다. 두 서비스는 서로 별개라서 각각 등록해야 합니다. 네이버 쪽 절차는 네이버 서치어드바이저 글에 정리해 두었습니다.

1단계: 속성 추가하기

서치 콘솔에 처음 들어가면 속성을 추가하라는 화면이 나옵니다. 속성은 “관리할 사이트의 범위”입니다. 구글 도움말 기준으로 두 가지 중 하나를 고릅니다.

구분도메인 속성URL 접두사 속성
입력 예시mysite.comhttps://www.mysite.com/
포함 범위모든 하위 도메인(www, m 등)과 http, https입력한 주소(프로토콜 포함)로 시작하는 페이지만
소유권 확인도메인 이름 공급업체(DNS 레코드)만 가능HTML 파일, HTML 태그, 애널리틱스, 태그 관리자 등
어울리는 경우도메인 관리 화면에 들어갈 수 있을 때DNS를 다루기 어렵거나 사이트 일부만 관리할 때

도메인을 산 곳(가비아, 카페24, 후이즈 같은 등록 업체나 Cloudflare)의 관리 화면에 들어갈 수 있다면 도메인 속성이 편합니다. www가 붙은 주소와 안 붙은 주소를 따로 볼 필요가 없습니다. DNS 설정이 낯설거나 제작사가 도메인을 관리하고 있다면 URL 접두사 속성으로 시작해도 충분합니다. 이때는 실제로 사이트가 열리는 주소를 https://와 www 여부까지 정확히 입력해야 합니다.

2단계: 소유권 확인하기

속성을 추가하면 구글은 “이 사이트가 정말 당신 것인지” 확인합니다. 아무나 남의 사이트 데이터를 보거나 설정을 바꾸면 안 되니까요. 구글 도움말이 안내하는 방법은 이렇습니다.

방법하는 일참고
HTML 태그구글이 준 <meta> 태그를 홈페이지 첫 화면의 <head>에 붙여 넣기직접 만든 사이트에서 가장 흔히 씀
HTML 파일 업로드구글이 준 파일을 사이트 최상위 폴더에 올리기파일 업로드가 안 되는 호스팅도 있음
도메인 이름 공급업체도메인 관리 화면에 구글이 준 TXT 레코드 추가도메인 속성은 이 방법만 가능
Google 애널리틱스 · 태그 관리자이미 설치된 추적 코드나 컨테이너로 확인해당 계정에 권한이 있어야 함
 
<!-- HTML 태그 방법 예시: 홈페이지 <head> 안에 넣기 -->
<head>
  <meta name="google-site-verification" content="구글이-발급한-값" />
  ...
</head>

워드프레스, 윅스(Wix), 스퀘어스페이스 같은 플랫폼은 대개 설정 메뉴에 서치 콘솔 연결 칸이 따로 있습니다. 구글 도움말도 이런 플랫폼은 플랫폼이 안내하는 방법을 따르라고 권합니다.

한 가지 꼭 기억할 점이 있습니다. 구글 도움말에 따르면 서치 콘솔은 확인용 태그나 파일이 계속 남아 있는지 정기적으로 검사합니다. 리뉴얼하면서 태그를 빠뜨리면 알림이 오고, 그대로 두면 권한이 만료됩니다. 그래서 구글은 확인 방법을 두 가지 이상 등록해 두기를 권합니다.

3단계: 사이트맵 제출하기

소유권 확인이 끝나면 메뉴의 색인 생성 → Sitemaps에서 사이트맵 주소를 입력하고 제출합니다. 보통 https://내 도메인/sitemap.xml입니다. 블로그가 있다면 RSS 주소도 같은 곳에 제출할 수 있습니다. 구글은 RSS도 사이트맵 형식의 하나로 받습니다.

제출하고 나면 같은 화면에서 구글이 파일을 읽었는지, 주소를 몇 개 찾았는지 볼 수 있습니다. 상태가 “성공”이 아니라면 파일 주소가 맞는지, 파일이 실제로 열리는지부터 확인하세요. 사이트맵과 RSS의 차이는 사이트맵과 RSS 글에서 자세히 다뤘습니다.

여기까지가 처음 한 번 해 두면 되는 일입니다. 그다음부터는 필요할 때 아래 도구와 보고서를 들여다보면 됩니다.

URL 검사: 페이지 하나 들여다보기

화면 맨 위 검색창에 내 사이트의 주소 하나를 넣으면 URL 검사 결과가 나옵니다. 그 페이지가 구글 색인에 들어 있는지, 안 들어 있다면 이유가 무엇인지 보여 줍니다. 실제 URL 테스트를 누르면 지금 이 순간 구글이 페이지를 가져갈 수 있는지도 확인할 수 있습니다.

새로 만든 중요한 페이지라면 여기서 색인 생성 요청을 할 수 있습니다. 다만 구글 도움말이 밝히는 한계가 있습니다.

  • 요청에는 할당량이 있고, 같은 주소를 여러 번 요청해도 더 빨리 처리되지 않습니다.
  • 크롤링에는 며칠에서 몇 주가 걸릴 수 있고, 요청했다고 검색 결과에 들어간다는 보장은 없습니다.
  • 주소가 많다면 하나씩 요청하기보다 사이트맵을 제출하는 편이 맞습니다.

처음 쓰는 분이라면 이 두 보고서만 알아도 충분합니다.

기본으로 최근 3개월 데이터가 보이고, 아래 표에서 검색어(쿼리), 페이지, 국가, 기기, 날짜별로 나눠 볼 수 있습니다. 예를 들어 “노출은 많은데 클릭이 적은 검색어”를 찾으면, 그 페이지의 제목과 설명문을 다듬을 실마리가 됩니다.

페이지 색인 생성 보고서: 어떤 페이지가 색인에 들어갔나

색인된 페이지 수와 색인되지 않은 페이지, 그 이유를 묶어서 보여 줍니다. 이 보고서를 볼 때는 두 가지를 기억하세요.

  • 모든 페이지가 색인될 필요는 없습니다. robots.txt로 막은 페이지, noindex를 단 페이지, 다른 주소와 중복인 페이지, 지운 페이지(404)는 색인되지 않는 것이 정상입니다.
  • 구글 도움말은 페이지가 500개 미만인 사이트라면 이 보고서가 꼭 필요하지 않을 수 있다고 설명합니다. 구글 검색창에 site:내 도메인을 입력해 보는 것으로도 대략 확인할 수 있고, 특정 페이지가 궁금하면 URL 검사를 쓰면 됩니다.

이 사이트의 사례

JM Studio 홈페이지는 이렇게 연결해 두었습니다.

  • 소유권 확인: 직접 만든 정적 사이트라서 HTML 태그 방법을 썼습니다. 메인 페이지 <head>에 google-site-verification 태그가 들어 있고, 페이지를 고칠 때도 이 줄은 지우지 않도록 관리합니다.
  • 사이트맵과 RSS: sitemap.xml과 Deep AI의 RSS 피드를 제출해 두었습니다. 새 글이 올라가면 두 파일이 함께 갱신됩니다.
  • 네이버: 같은 작업을 네이버 서치어드바이저에도 따로 해 두었습니다.

흔한 오해

1

등록하지 않으면 구글에 안 나온다오해

구글은 링크를 따라가며 페이지를 스스로 찾습니다. 서치 콘솔 등록은 검색에 나오기 위한 필수 조건이 아니라, 더 잘 알리고 상태를 확인하기 위한 도구입니다.

2

등록하면 바로 검색에 나온다오해

색인 생성 요청이나 사이트맵 제출은 구글에 주는 신호일 뿐입니다. 크롤링에는 시간이 걸리고, 검색 결과에 들어갈지는 구글이 판단합니다.

3

색인 생성 요청을 반복하면 빨라진다오해

구글 도움말은 같은 주소를 여러 번 요청해도 더 빨리 크롤링되지 않는다고 밝힙니다. 한 번 요청했다면 기다리는 것이 맞습니다.

체크리스트

  • 서치 콘솔에 속성을 추가했다 (가능하면 도메인 속성)
  • 소유권 확인을 마쳤고, 확인 방법을 두 가지 이상 등록했다
  • 확인용 태그나 파일이 리뉴얼 뒤에도 남아 있다
  • 사이트맵을 제출했고 상태가 “성공”이다
  • 블로그가 있다면 RSS 주소도 제출했다
  • 중요한 새 페이지는 URL 검사로 색인 상태를 확인한다
  • 한 달에 한 번쯤 실적 보고서로 검색어와 클릭을 살핀다
  • 네이버 서치어드바이저에도 따로 등록했다

자주 묻는 질문

구글 서치 콘솔에 등록하지 않으면 구글 검색에 안 나오나요?

그렇지는 않습니다. 구글은 링크를 따라가며 새 페이지를 스스로 찾기 때문에 등록하지 않은 사이트도 검색에 나올 수 있습니다. 서치 콘솔을 쓰면 사이트맵을 제출해 페이지를 알리고, 색인 상태와 검색 실적, 문제를 직접 확인할 수 있습니다.

도메인 속성과 URL 접두사 속성 중 무엇을 골라야 하나요?

도메인 설정(DNS)을 바꿀 수 있다면 도메인 속성을 추천합니다. www가 붙은 주소와 안 붙은 주소, http와 https를 모두 묶어서 볼 수 있습니다. DNS를 다루기 어렵다면 URL 접두사 속성을 만들고 HTML 태그나 HTML 파일로 소유권을 확인하면 됩니다.

소유권 확인용 태그를 나중에 지워도 되나요?

지우면 안 됩니다. 구글 도움말에 따르면 서치 콘솔은 확인 토큰이 계속 있는지 정기적으로 검사하고, 더 이상 확인할 수 없으면 알림을 보낸 뒤 유예 기간이 지나면 권한이 만료됩니다. 홈페이지를 리뉴얼할 때도 확인용 태그나 파일을 그대로 옮겨야 합니다.

새 글을 올렸는데 색인 생성 요청을 꼭 해야 하나요?

꼭 해야 하는 것은 아닙니다. 사이트맵에 새 주소가 들어가 있으면 구글이 찾아갑니다. 빨리 알리고 싶은 중요한 페이지가 있을 때 URL 검사 도구에서 색인 생성을 요청할 수 있지만, 할당량이 있고 같은 주소를 여러 번 요청해도 더 빨리 처리되지는 않습니다.

서치 콘솔과 네이버 서치어드바이저를 둘 다 해야 하나요?

둘 다 하는 것이 좋습니다. 두 서비스는 서로 별개라서 한쪽에 등록한 내용이 다른 쪽에 반영되지 않습니다. 사이트 등록, 소유 확인, 사이트맵 제출을 각각 해 두면 구글과 네이버에서 모두 상태를 확인할 수 있습니다.

구글 등록, 어디서부터 해야 할지 막막하다면

서치 콘솔과 네이버 서치어드바이저 등록, 사이트맵과 RSS 설정까지 홈페이지가 검색에 잘 보이도록 점검하고 연결해 드립니다.
